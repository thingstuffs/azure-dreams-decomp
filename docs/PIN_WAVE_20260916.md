# Round 35: a bounded joint-width and source-repair wave

Started from 6,148 pins in 1,295 rows, with a clean working tree. Fixed compiler
recipes throughout; no new asm, volatile qualifiers, fences, fake dependencies,
flags, or one-trip blocks. Work packets and experiment scripts are retained in
`work/native_lane/r35_parent/` and `work/native_lane/r35_sol_far/`.

## Assessment

The remaining population is difficult, but the evidence does not establish an
irreducible floor. The prior round-33 instrument work landed nothing; round 34
landed 33 pins after substantial model/tool work; the subsequent unexplained-near
Sol pack was 0/12. These results justify stopping repeated searches with the same
menus. They do not establish that the C cannot be reconstructed.

Keep the independent verifier, window gates, fixed recipes, source hashes, and
scaffolding checks. Change the unit of investigation: use related values and
actual C semantics, rather than assuming a pin's operands identify every variable
that needs changing. Find one exact example, measure single-change controls, then
run a small CPU cohort before commissioning infrastructure or additional agents.
Screen distance is useful for ranking but not a causal diagnosis or proof. A
fix can require intermediate candidates that are further from retail.

## Exact source changes and controls

- `dungeon/func_8009ED80`: both offset coordinates become `u16`; remove their
  shared `ASM_USE2`. Erasure alone: screen 16 / verifier 13. Narrow x alone:
  36 / 31; narrow y alone: 28 / 15; narrow both: 0 / exact. Both final uses
  already mask with `0xffff`, so moving truncation into the declarations is safe.
  Related `func_8009EF28` admits the same change, removing one pin while its two
  register bindings remain. Retesting each binding and both together was negative.
- `dungeon/func_800C6A2C` and `func_800C8FE8`: remove both remainder/result
  register bindings and declare only the merged result `s16`. The initial joint
  candidate narrowed both locals, but controls showed narrowing the remainder
  was unnecessary. Both values range from 0 to 254: the divisor is a nonzero
  byte and the dividend is masked to 16 bits. Two pins removed per function.
  Existing t37 couples a variable's retype to erasing that variable's own pins;
  this fix also erases the related remainder's binding.
- `dungeon/func_81876014`: widen the copied x base and edge from `u16` to `s32`
  together and remove the edge keep. Restoring only the edge's type fails at
  verifier distance 19; restoring only the base's type fails at distance 1.
  All externally observed x values are halfword stores; the intermediate is
  at most 65551 and its low halfword is unchanged. Existing pins on other values
  remain. One pin removed.
- `dungeon/func_818C2FAC`: declare the saved angle `s16`, remove the keep on the
  unrelated constant object type. Keep object type `s32`: minimization proved
  narrowing it unnecessary. The angle was already explicitly converted to
  `s16` before its first use. One pin removed.
- Sol's `dungeon/func_8184AF90`: replace the bare `return;` in an `s32` function
  with `return (s32)effect;`, removing the unused result local and its register
  binding/keep. This expresses the return value the old asm pins preserved.
  Independently verified exact by the lane; two pins removed.

## Next steps

Prefer small probes that decouple (a) which related locals change type and (b)
which pins are removed. The demonstrated gaps are joint width, copy-connected
pin erasure, and changes to a different live value. Keep candidate count bounded
and review arithmetic ranges before landing. A general narrowing transform needs
range/use guards; byte equality alone does not justify arbitrary changes in the
portable C interpretation.

Audit remaining non-void bare returns with pinned result locals: the Sol finding
is a concrete source repair, and is a better next hypothesis than another broad
allocator-spelling search. Do not interpret this wave's small sample as a forecast
for the other 6,000 pins, or the far lane's negatives as impossibility results.

## Landing and gates

All seven candidates landed through `apply_candidates.py` with fresh source
hashes and independent exact verification. The follow-up T2 pass removed zero
additional pins. Census: **6,138 pins in 1,292 rows**, down **10 pins / 3 pinned
rows**, with 7 functions changed. Unscored arms are unchanged and hidden asm did
not increase on any changed row. No full transform cascade was run: this was a
bounded wave.

`promote_honest.py` registered the previously proven true name `func_80025814`
for row `dungeon/func_81876014` in region `jtbl_1895C70`; no new address was inferred,
no compiler recipe changed, and no assembler dial was added.

All 6 changed overlay windows MATCH (154 s, no retries), with 2,169 unchanged
windows reused by input identity. SLUS SHA-1 MATCH (884 TUs, unchanged recipe).
Row database check and whitespace checks pass. Status and level ledgers refreshed.
Registry regeneration removed 51 unrelated historical `cfg_corrected` annotations;
those annotations were restored, leaving only the intended true-name row change.
