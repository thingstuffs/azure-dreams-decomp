# Partition-only owner proof review

The bounded candidate review found no defect in the partition-only data-ownership path. `module_anchor` chooses an actual incoming collector row for an empty-member owner; `physical_descriptor` includes every incoming function in the selected owner's complete physical TU. `check_partition_record` requires the real collector's full pipeline and unmasked retail proof across its remainder and destination units, then requires direct genuine equality and unmasked retail comparison for the selected complete owner TU. It deliberately permits an unrelated collector remainder's genuine mismatch. The ownership loop processes each contributing parent row even though `members` is empty, and emits schema 5 with an explicit partition-only list.

The placement boundary remains separate: `certificate_reason` and the certifier refuse a partition-only owner before issuing a whole-row certificate; `valid_placements` has no row to grant. The isolated gate and `row_db.check_slus_partition_plan` both validate a partition-only owner even when the partition plan is empty, closing the empty-plan bypass in those consumers.

`tests/test_partition_only_evidence.py` imports the private candidate modules by exact path. Nine tests pass. Positive cases use two contributing parents and a selected two-function physical TU while both unrelated remainder genuine comparisons fail. Negative cases reject a missing incoming function, incomplete or mismatched full-TU proof, masked comparison, unknown selected LNK record, stale fingerprint, wrong recipe, duplicate or omitted physical unit, omitted remainder, forged contributor, and placement attempts. A mocked ownership run confirms `A.process_row` is invoked for both actual parent rows instead of vacuously skipping an empty member list. The isolated-gate test confirms `validate_context` runs for an orphan partition-only module with an empty plan. The row-database test calls the actual candidate `check_slus_partition_plan` with both missing and explicitly empty plans and rejects the orphan while preserving the empty legacy case.

These are source-contract tests using explicit synthetic collector records and mocked build outputs. They do not replace a fresh `A.process_row` measurement, named data-piece/ELF proof, full-image link, or production activation. Candidate tool sources were not modified in this review. After the initial eight-test review, the root changed only the ownership prover's top docstring and added the row-database empty-plan guard; the current hashes and nine-test receipt in `review.json` bind this final candidate scope. All nine candidate tool hashes match the frozen `tool_pins.json` set; the build `configure.py` hash is recorded for package binding, not claimed as part of this focused evidence review.
