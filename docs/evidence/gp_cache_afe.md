# AFE cache ownership

The cache at `0x80080AFE` is a two-byte value used by `func_80044618`.
Its previous `extern u16 D_80080AFC[2]` declaration conflated it with the adjacent
selector used by `func_8004437C`. The new fragment declares `extern u16 D_80080AFE`;
its owning translation unit defines `u16 D_80080AFE = 0`. The function body only
changes the two lvalue spellings. Its existing plain 2.7.2 recipe is unchanged.

## Storage and behavior review

The complete [32-word retail map](gp_cache_afe/retail_44618_32.dis) has a halfword
load at `80044638` and store at `80044678`, both at GP displacement `0x16a`,
resolving to AFE. It caches `(u32)VSync(1) >> 8`, masked with `0x1ff` for mode 2
or `0xff` otherwise. On change it calls `func_800542BC`; otherwise it returns 2.
The earlier “controller id” interpretation was unsupported and is removed.
Return and callee declarations are preserved; this change does not settle that
callee's broader ABI.

The [scoped storage audit](gp_cache_afe/storage_audit.json) separately checks all
100 words of 4437C and all 72 words of 4425C. The former directly accesses AFC,
never AFE; the cache directly accesses AFE, never AFC. Their halfword accesses
and distinct uses support separate present C objects. The source scan found only
these two direct AFC users. Indexed access through the incomplete AF0 array in
4425C has no established runtime bound, so this does **not** prove the absence
of indirect accesses to AFE. The unchanged addresses and full retail bytes
preserve those possible accesses. No historical translation unit or original
symbol name is asserted.

AFE is exactly the two zero bytes at offset `0xbe` of `assets/54240.bin`
(retail file offset `0x542fe`). The module carves these bytes into real `.sdata`,
without claiming adjacent storage. A canonical two-byte AFE label is added to
`config/slus_006.14.symbols.txt`; normal Splat generation creates its assignment,
and the existing ownership filter removes that assignment for the C-owned link.
AFC's separate absolute symbol remains. No generator/filter exception is needed.

## Validation

The [private full-link receipt](gp_cache_afe/private_link_receipt.json) records
normal Splat registration, exact storage/carve/symbol checks, unchanged outside
4437C object bytes, and fresh stock/genuine ASPSX 2.79 equality: all 32 retail
words, zero masks, using the newly linked symbol map. The full 524288-byte image
matches retail SHA-256
`ae19d8d4bdd2db9a933b1e44d70dd61be670781e441d7cb37da85250a7aed31f`.
Its temporary manifest evidence path/header list reflect that pre-integration
experiment, not the final manifest. Reproducer:
`work/native_lane/gp_cache_afe_link/probe.py` (expects the 18-module baseline).

Production confirmation is recorded in
[the strict ownership receipt](gp_cache_afe/ownership_receipt.json), generated by:

```sh
flock build_ovl/work/land.lock python3 tools/fidelity/prove_slus_ownership.py \
  cache_afe --output docs/evidence/gp_cache_afe/ownership_receipt.json
```

The module is a present ownership unit, not an L4/L5 placement claim. No new pins,
recipe changes, production assembler changes or compatibility pass removals are
part of this repair. Earlier AF3 cohort experiments retain their historical
results; the cache no longer needs to join that cohort to obtain genuine proof.

Production integration passed the pinned-recipe SHA-1 gate and strict fresh
ownership proof. The outside 4437C object remains unchanged. The runtime-directory
pilot is recertified. Production has **19 ownership units, 873 physical / 884
logical rows, 197 dependency records and 29 remaining GP rows**. Only the cache's
dependency record is removed. An automatic snapshot (`bac723e1`) captured its
source and generated recipe during integration; the companion evidence commit
records the canonical symbol, manifest, proof and dependency update.
