# r76 measurement protocol v2: a small, fair model A/B that is mostly progress (2026-09-23)

Status: RUNNING since 10:08Z (codex + Gemini arms); the Opus/Sonnet packs are built and wait for the coordinator.
v1 (every arm on the same 120 rows, 120 lanes) is retired: too big, and not progress. `python3 tools/lanes/ab_plan.py
paired` still regenerates it.

## The owner's constraints

Small and mostly progress, but fair: "luna could solve 9/10 super trivial rows and astra 1/4 and we decide that's not
good". So every arm must see the same difficulty mix, no row is wasted on a repeat, a small overlap set gives a direct
head-to-head, and failed rows climb the ladder.

## Design (generated by `python3 tools/lanes/ab_plan.py plan`, seed 76)

- **Pool.** Pinned rows (not ovmovie, not slus) that no kit-era strong lane (astra/Opus, lane r68_* on) served at their
  current text, and that no launched lane of any arm's tier (luna6, sol6, astra, opus, sonnet, agy) served at their
  current text - so the tier served-guard refuses nothing and every arm's rows are new to it.
- **Strata.** pin band (1-2, 3-7) x container (dungeon | other) x difficulty tercile. Difficulty = the cc1 listing
  distance of erasing EVERY pin of the row (lines added + removed in the normalised listing diff, `tools/xform/screen.py`
  - the same diff the pack's rows.md shows the lane; ~0.1 s a row); a row whose erased text does not build goes to the
  hardest tercile. Terciles are cut within each band x container.
- **Single serve, stratified random assignment.** Per band, the eligible rows are ordered by stratum (random within), a
  systematic sample of 60 keeps the strata proportions, 5 of them are the overlap set, and the other 55 are dealt through
  shuffled blocks of 11 slots (luna6, sol6, agy, opus, sonnet 2 each, astra 1): consecutive rows of one stratum go to
  different arms. Per band: luna6, sol6 (+`residual_to_form`), agy (Gemini 3.8 Flash High), opus, sonnet 10 rows (2 packs)
  each, astra 5 (1 pack) - astra is expensive (weight 35).
- **Overlap calibration set.** 5 rows per band served to ALL six arms (lanes `r76o_<arm>_<band>`). The `r76o_` prefix is
  outside land_finished2's `r7[0-9]_*` glob, so none of them lands until every arm has finished; then the best candidate
  per row (most pins removed, tie -> cheapest arm) is landed by hand.
- **8+ band.** Cluster packs (`--cluster 3-5`, one rank-0 cluster per row, partial landing asked for): astra only, 2
  packs (`r76_astra_b8c_1..2`, chained after the astra arm), plus Gemini freely through the feed below.
- **Escalation (progress).** After the arms finish, `python3 tools/lanes/ab_plan.py escalate --out F` lists the rows a
  single-serve lane failed (still at the text it was served) for the next tier: luna6/agy -> sol6 -> opus|astra
  (alternating), minus rows that tier already served at this text. Record the conditional success rate per step (the
  rate of tier B on rows tier A failed). Fable only for rows every arm failed, and not in this round.
- **Gemini beyond its arm.** `tools/lanes/gemini_feed.sh` (one background job): probe agy (exact OK, no limit words) ->
  `ab_plan.py feed` (escalation leftovers, then never-strong-served rows by band, then 8+ cluster packs; the A/B rows,
  rows of unfinished r76 lanes and the overlap rows are reserved; the agy tier guard never repeats a row at the same text)
  -> `pool.py --model agy --kit --no-land` (lanes `r76_gemf_*`, landed by land_finished2). On a failed probe (limit) it
  sleeps 1 h and probes again, so it resumes after the weekly reset (~18 h); a lane cut by the limit gets `limit_cut.txt`
  and its rows count as unserved. Deadline 48 h; `touch work/native_lane/STOP_GEMINI_FEED` stops it; one completion line
  `GEMINI_FEED_END`.

## Analysis

1. **Rates per stratum.** For each arm: exact rows / rows served in each stratum (band x container x tercile), and the
   arm's rate re-weighted to the pooled stratum mix (direct standardisation), so an arm that happened to draw easier rows
   gets no credit for it. Report n per cell; with 10 rows per band per arm (5 for astra) a cell is 1-4 rows, so read the
   band-level standardised rate and treat cell rates as descriptive.
2. **Cost.** `python3 tools/lanes/ab_report.py --glob 'r76_*_b12_*' --glob 'r76_*_b37_*' --ok-only` (per band: one glob):
   weighted cost per exact row and per pin removed (tokens x weight / 1e6), wall-minutes per exact row, caps fired. Opus
   is not apples-to-apples with codex; Sonnet is a range [0, Opus]; Gemini is 0 this window.
3. **Head-to-head on the overlap set.** `--glob 'r76o_*'`: for each pair of arms the 10 identical rows as a 2x2 table
   (both exact / only A / only B / neither) and pins removed; the discordant counts (McNemar) are the comparison. At 10
   rows only large gaps show (e.g. 8/10 vs 2/10); the overlap set calibrates the single-serve rates, it does not replace
   them.
4. **Escalation.** For each step (luna6 -> sol6, agy -> sol6, sol6 -> opus/astra): rows escalated, solved, pins removed,
   weighted cost: the conditional success rate that decides where a failed row should go next.
5. **Decision rule** (for the next round's routing): per band, the arm with the lowest weighted cost per pin among arms
   whose standardised exact rate is not clearly worse (overlap discordance not significantly against it); Gemini while
   free goes first on everything it can take.
