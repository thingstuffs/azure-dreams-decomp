Azure Dreams decomp · type consolidation pilot

One object, one name

Today every function carries its own private guess at the game's data: the same actor, table or global appears under different names and types in different files. The pilot replaces those guesses with shared, named types that every file includes, while every function still compiles to the exact retail bytes.

PILOTLanded 2026-09-28: 243 functions now use the shared types, every one byte-exact, with all 179 affected overlay windows and the SLUS image matching retail. The first three code comparisons below are landed, verified diffs; the last one is an illustrative sketch of where this is heading.

What changes and what doesn't

The bytes are the contract

UnchangedRetail bytes

Every touched function is re-verified and every overlay window and the SLUS image are gated. A spelling that changes one byte is refused and reverted.

ChangesOne definition per object

Shared headers under include/game/, used by the executable and both overlays alike.

ChangesNames with evidence

A field is named when its role is clear from several functions; otherwise it keeps unk_XX or a plain descriptive name.

Checked per rowCodegen side effects

Fields of one struct can share an address register where separate symbols don't; retail's own code shows which the original used.

Owner rulings, 2026-09-28
  1. Consolidate per-function views into shared game types.
  2. Name at relatively high confidence; revisit if wrong. Unknowns stay unk_ or get a helpful descriptive name, never a claim they are something they're not.
  3. Shared objects have one definition across all binaries.
  4. Resolve "accessed as both" unions where the evidence allows.
  5. Pilot first; the approach can change with more evidence.
