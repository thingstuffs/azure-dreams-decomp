# Devkit card server: functions without C, recovered (opus_nobody1)

MAIN carries a devkit build of the memory-card server at file offsets 0x269000..0x275800. Its assertion
strings name the source `c_server.c`, and its internal calls and jumps place it at 0x80400000
(`ledger/instance_load_regions.jsonl`, `config/link/main/ll34_269000_80400000.json`; RAM above 2 MB, so
it is not reached on a retail console). Its rows keep `main/func_8001xxxx` ids (file offset + 0x7FDB0000);
`true_name` and the link-list VMA carry the 0x804xxxxx identity.

The address census (`tools/codemap/target_census.py`) found 14 calls into this program that land on a
function prologue with no C row (class MISSING). Twelve of them are the server's builds of existing card
UI functions: the same instruction sequence with different structure offsets (and, for calls into the
executable, different targets: the server was linked against a devkit build of the executable). This
cohort recovers ten (seven in the first batch, the three menu-table builds in the second):

Each body compiles to its entire retail extent at stock 2.7.2 -G0 (2.6.3 and 2.7.2-cdk give the same
bytes) without assembly, register pins, goto, volatile or compatibility macros. Callees that have no
readable name at their true address keep the address spelling in one new header,
`include/frontend/card/server_imports.h`; the menu-table builds share `include/frontend/card/server_menu.h`
(entry block and primitive types; each table is the same shape - settings, entry pointers, entry blocks,
primitive words - at a different object offset and length). The three executable calls (0x80051DE4, 0x800514A8, 0x80051FBC)
are inside other functions of the retail executable and stay address-named.

Each row is its own home placed in `ll34_269000_80400000` at its true address; the byte maps' unresolved
spans become proven code. Registration reused the identity-keyed shared-placement script of the
nearmatch cohort; the row registry and the link graph are regenerated by their tools.

## True-base pilot: reset_card_selection_state

Row `main/func_80019908` (MAIN +0x269908, 64 bytes) was compiled and linked at its placeholder 0x80019908, while six
server call sites jal 0x80400908 and therefore spelled the callee `func_80400908`. The row is promoted to its true
base like the earlier MAIN rowbase rows: a proven record in `config/overlays/main.rowbase.jsonl` (delta 0x80197000),
split `true_name` func_80400908 (the stale true_name func_8002C908 and its alias `run_setup_indices`, which nothing
used, are retired), and the names.tsv line moved to 0x80400908. The callers now call
`reset_card_selection_state()`; two of them see its prototype in `frontend/card.h` and lose their local declaration.
The unit links at 0x80400908 and every image stays byte-identical (make check 1518/1518).

`tools/headers/rebase_placeholder_rows.py` applies the same promotion to every placeholder-linked server row the
address census finds (class C_PLACEHOLDER): 41 of 45 now link at their true address. It holds a caller whose
declaration returns a value that the function's own prototype does not (7 callers), skips a row that a native
module binds by name (invoke_callback_with_zero, also a TOWN module member) and the three libcard assembler rows.
