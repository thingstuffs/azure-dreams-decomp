# 81550 message-mode group: ownership and declaration repair

The four-function candidate now matches all **156 retail words** through
both genuine ASPSX 2.79 and the existing private generic assembler correction,
with zero masks. Its private full image also matches retail. Production remains
unchanged: stock assembly still makes a one-instruction GP address where retail
and genuine ASPSX retain an absolute address pair. This is a prepared source and
ownership repair for the coordinated assembler transition, not a production gate
or L4/L5 placement certificate.

## Separate causes, concrete repairs

The initial candidate defined only the mode word at 81550 and preserved the
existing bodies and declarations. At default CDK, DCEC differed; with its existing
`-fno-schedule-insns -fno-delayed-branch` settings, the two message builders
instead differed. DF8C also retained a separate assembler mismatch at either
recipe. The [initial matrix](gp_message_mode_81550/initial_matrix.json) is a
scoped rejection record, not evidence of a missing compiler. Nonzero positional
retail counts are not closeness scores across differing lengths.

Reading every DF8C retail instruction identifies a second real word at 8154C:
the function takes its absolute address to encode it into the message, then
stores a word through GP at the end. Defining `s32 D_8008154C = 0` alongside
`s32 D_80081550 = 0` fixes that genuine-ASPSX store. The two definitions replace only
eight zero bytes at offsets B0C/B10 of asset 54240; 81548 remains a distinct external
word reached by the existing address and neighbor-store expressions. No larger
array or padding is inferred from adjacency.

DCEC's sixteen-byte B6C declaration was the other cause. The
[initial data audit](gp_message_mode_81550/b6c_initial_audit.md) properly rejects
calling B6C an ordinary string solely from its `23 00` prefix. The
[downstream review](gp_message_mode_81550/b6c_primary_review.md) follows the actual
script consumer: the pending address enters the bytecode cursor; opcode 23 selects
39B84, which installs no-op 38A08 without consuming an operand; the dispatcher
reads the following zero and leaves dispatch. Those two bytes are a complete
script view. The original allocation size and constness remain unclaimed; no
B6C storage is owned here.

With `extern char D_80080B6C[2]`, CDK emits a bare `la` pseudo-op for the script
address. Genuine ASPSX expands its two instructions, preserving the empty
indirect-call delay slot and the retail register roles. The old special flags
are unnecessary at this measured source shape. Incomplete `[]` retains the same
split-address issue as `[16]`; that negative control is recorded in the
[incomplete-array trial](gp_message_mode_81550/incomplete_array_matrix.json).
No function body, register pin or volatile access was added. The existing pins
in DE88 and DF8C remain, so this proof makes no pin-free or placement claim.

The [feature map](gp_message_mode_81550/feature_attribution.md) and
[byte-signature result](gp_message_mode_81550/lineage.json) preserve attribution.
The automatic classifier is inconclusive; the full manual site map identifies
the separated two-register split address. The result does not depend on a
compiler-sweep ranking or an asserted historical translation-unit boundary.
