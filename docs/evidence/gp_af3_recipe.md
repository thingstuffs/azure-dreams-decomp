# AF3 shared-owner recipe evidence, 2026-09-24

`D_80080AF3` is referenced by `w_8004437C` and `w_8004450C`, whose current retail-exact sources use different registered compiler recipes: CDK 2.7.2 and plain 2.7.2, respectively, both with empty flags. `w_80044618` shares the nearby AFC state access. These isolated measurements ask whether the *unchanged* sources can use one of the existing recipes or CDK with the single dialect flag `-mmips-as`. They do not establish data ownership or reconstruct an original translation unit.

The durable recipe receipts are [forward.json](gp_af3_recipe/forward.json), [reverse.json](gp_af3_recipe/reverse.json), [dialect.json](gp_af3_recipe/dialect.json), and the one-row [44618 cache trial](gp_af3_recipe/cache44618.json). Each private SLUS view first calibrated to the retail image. The recorded dynamic snapshots were unchanged across the runs. A live check after packaging found 17 production modules, 874 physical C edges, and 884 logical rows. The current source hashes remain `4c5295998419e52082e17b3dccd35b5826206aa04544163b3e6c5dd1598e5819` for `w_8004437C` and `c2f99b3c4d77da268daf069e0f45ceafd1722b89e0cacb668a29b2e8fbe6c3f4` for `w_8004450C`. The row registry's `src_sha` instead identifies each frozen `raw/slus/` copy; the trials compiled the current `src/slus/` files.

## Retail source map and first pointer trial

The scoped [4437C source map](gp_af3_recipe/source_map.md) includes the [full 100-word retail disassembly](gp_af3_recipe/retail_100.dis), registered and dialect object disassemblies, and the dialect compiler assembly. It records a `0x28` frame saving `$s0`–`$s3` and `$ra`: `$s0` holds the indexed `D_8006E704` pointer-slot address, `$s1`/`$s3` hold the mode across relevant calls, and `$s2` preserves the entry index for later slot recomputation. Retail holds the early `D_80080AF4` base in `$a1` for **two** indexed reads, then materializes a **fresh** `$a0` base after `Control_CD` for the indexed store in `func_8003F320`'s call delay slot. No AF4 pointer is live across that call. The map also lists the AF3 byte access, AFC halfword accesses, E704 pointer-slot accesses, and each call boundary's live values.

The direct raw-SLUS [lineage scan](gp_af3_recipe/lineage.json) finds only the store-filled call slot, a family-neutral scheduling signature. It finds no `$at` macro store, split store, held page, split-la, zero-copy, or return-copy signature; classification is **insufficient evidence** with no compiler family. The observed dialect residual is narrower: unchanged `4437C` under `-mmips-as` folds its **first** AF4 indexed read to `lw $2,D_80080AF4($2)`, expanded through `$at`, although it emits the early base. Its **second** read keeps the held `$a1` base. After `Control_CD`, it folds the **final** store to `sw $3,D_80080AF4($2)` rather than using the fresh base and call delay slot. The [dialect receipt](gp_af3_recipe/dialect.json) records the exact aligned word regions.

The first [explicit-pointer C variant](gp_af3_recipe/v1.c) names early `read_slots` and post-call `write_slots` pointers. Its [object comparison](gp_af3_recipe/v1.json) remains 100 stock words at aligned distance 16 from retail; genuine ASPSX emits 108 words at aligned distance 31 from retail. There was no full-image gate for this variant. A separate [token proof](gp_af3_recipe/v1_token_proof.json) compares the existing v1 object with the unchanged-C `-mmips-as` object: all 100 instruction tokens and relocations are identical, and the compiler assembly differs only in its `.file` directive. Their ELF file hashes differ because of that file metadata. This explicit-pointer spelling produced no instruction change.

The next step is to identify the compiler's address-folding mechanism behind the first load and final store **before** making more C variants. Any candidate must still pass stock, genuine-ASPSX, and full retail-image gates. The 44618 cache result is a one-recipe control, not an ownership or binding proof. Separate `owned_scalars` diagnostics are not included here because their definitions have not passed an ownership/link gate. These measurements make no impossibility claim about C shape or the eventual shared ownership boundary, and the lineage scan does not attribute a compiler family.
