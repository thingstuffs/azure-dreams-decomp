# Type consolidation pilot (r78) - design

Model: claude-opus-5-5[1m]. Lane: `work/native_lane/r78_types_pilot/`. Nothing under src/, include/, config/ or
tools/ was edited; `apply.sh` lands everything under the landing lock (dry run: 243 rows, 0 skipped).

## 1. Data-symbol naming: extend the existing alias layer, add no new mechanism

`config/names.tsv` is already name-agnostic. `tools/build/ccproc.py` builds `{readable: original}` from every row and
rewrites `\breadable\b` on every non-string line of the gcc `-S` output, `.extern` lines included. It does this before
maspsx, `as`, the window link and the SLUS link. `tools/gate/match.py::_canonicalise_names` (the scorer's copy)
does the same. So a data row

    0x8006CCD8  D_8006CCD8  dirStepX  <evidence>

lets C say `dirStepX` while the assembler input still says `D_8006CCD8`. The objects are identical: no relocation
name changes, no absolute symbol is added, and the undefined_syms files are unchanged. Every binary links the same
address because the symbol is still the D_ one.

I checked this against every consumer of names.tsv:

| consumer | data row effect |
|---|---|
| ccproc.py (gate cc.sh, SLUS build via configure.py, verify SLUS path) | canonicalises the name (proven: lane listings through `ccproc --names-only` with the lane table equal the pinned listings, 205/225 steps rows byte-identical text; the rest differ only in `%lo(D_80083460+2)` vs `%lo(D_80083462)` spelling, same bytes) |
| gate/match.py (per-row scorer) | same table, same rewrite. I ran `_canonicalise_names` in-process with the lane table on 4 candidates: its output equals ccproc's byte for byte, and no readable name is left |
| verify.py `canonical_spelling` | only rewrites identifiers the file DEFINES as functions (`name(...) {`), so data names are untouched |
| build/slus_partitions.py `read_aliases` (partitions, row_db, slus_iso, slus_module_context) | skips every row whose canonical column is not `func_XXXXXXXX`, so it is safe |
| gate/overlay_local_gate.py, overlay_func_compare.py | resolve readable -> original by the `(func|D)_<addr>` regex, so they would even link an un-canonicalised name |
| apply_names.py | refuses (`no defining row`): a data symbol has no defining row, so apply.sh appends the rows directly |
| decl_census.py, evidence.py | read the table as aliases; evidence.py documents it as "function renames" (cosmetic) |

Recommended follow-up: an `apply_names.py --data` mode. It would skip the defining-row test, use the same collision
test (the name must not appear as an identifier in src/ or include/), and journal to `ledger/names.jsonl`.

Hazard: a TU that declares both the readable name and its D_ original yields two `.extern D_x,size` lines after
canonicalisation. A migrated row never does this, because its local D_ declaration is removed. SLUS module TUs
(several members in one .s) could do it. slus/w_80042BDC verified exact in its module context, but no module where
two members disagree was exercised.

## 2. Where shared types live

- `include/shared/<object>.h`, one header per object or family (`dir_step.h`, `dungeon_status.h`). The header
  holds the extern with its readable name, the typedef, and the per-field evidence comments.
- The headers use plain C types (`short`, `unsigned short`, `void *`) and include nothing. The first header
  included common.h, and 2 of 231 rows failed to build with it: those rows carry their own `typedef ... u8/s32`
  and never include common.h first.
- Migrated rows include the header explicitly (inserted right after `#include "common.h"`), and each row's local
  copy of the type or extern is removed.
- **Not via common.h yet.** common.h pulls game.h/globals.h into every TU, and local typedef names collide:
  `DungeonStatus` is a local typedef for a different object in dungeon/func_8028B110, and `DungeonGlobals` is one in
  dungeon/func_800BACA4. That is why this pilot's type is `DungeonGlobalStatus`, and apply.sh's preflight refuses
  any collision. Fold the headers into common.h only after a tree-wide collision lint passes, which is the same
  test apply.sh runs.
- `include/records/Rec_*.h` are generated by the struct census ("never hand-edit") and are not the home for
  hand-recovered types. `Rec_D_80083460.h` (span 0x10, 5 functions) is superseded by `dungeon_status.h` and should
  be dropped from the census input when this lands.

## 3. Naming-evidence rule applied

A name must be proven by what the code does, without asserting anything beyond it:

- `dirStepX` / `dirStepY`: the retail bytes are {1,1,0,-1,-1,-1,0,1} and {0,1,1,1,0,-1,-1,-1}. Every row indexes
  them by a direction 0..7 (angle >> 9) and adds them to the entity's grid x byte (+0x24) or grid y byte (+0x25).
  func_807B0110 adds them to the first and second ground axes of a world position. "X/Y" is how the tree already
  spells those axes.
- `DungeonGlobalStatus` / `dungeonStatus`: only the DUNGEON overlay and the SLUS dungeon-entity helper
  (w_80042BDC) touch it. It holds a flag word and counters, so it is named "status", not "state machine" or
  "floor".
- Fields are named only when every use proves the meaning. `flags` (0x02) passes: every use is a bit test or bit
  set. `unk_0A` stays `unk_`, with a comment that it is a counter (+1/-1 at every write), because what it counts is
  not proven. Everything else stays `unk_XX`, with its access census in a comment.
- Randomizer/developer names (docs/SYMBOLS.md) come first when they exist; neither object has one.

## 4. The two recovered types

### 4.1 `short dirStepX[8], dirStepY[8]` (SLUS .data 0x8006CCD8 / 0x8006CCE8)
Access census, 231 rows, from the cc1 listings of the pinned texts, which equal retail order:

## 5. Codegen hazards measured

1. **Shared %hi (split cells: 2.7.2-cdk, 2.8.x).**
   - A struct member `g.f` whose address is reused compiles to a base, `lui/addiu &g` then `op off($r)`. A single
     use compiles to `lui %hi(g+off)` / `op %lo(g+off)`, which is the same bytes as a separate symbol.
   - Retail's lui pattern in all 836 rows is consistent with ONE struct. With plain field spelling, 234/234
     automatic rows and 20/20 sample rows are exact, including the D2 rows that had two separate symbols' luis in
     one function (different basic blocks, so cse never merges them).
   - The spelling decides the result, not the struct. A pointer-cast view `((u16 *)&dungeonStatus)[5]` compiles
     to the `%hi(g+10)` direct form and misses. All 53 automatic failures were such views: 27 `u16[]`, 21 `s32[]`,
     4 `s16[]`, 3 `u8[]`. The natural `dungeonStatus.unk_0A--` is exact on every one tried (8/8).
2. **Non-split cells (stock 2.7.2 / 2.6.3, macro assembler).** A field access becomes `la g+off` / `lhu g+off`.
   Retail rows func_800A065C and func_800A4DA8 (registered 2.7.2-G0) instead show `la g` + `off($r)`, which is the
   split form. With the struct, both rows' natural one-line spelling is exact at 2.7.2-cdk-G0. The pinned text is
   not exact there (total 6 and 7), so this is a rule-4b / 09-24 coherence repair that removes an `ASM_KEEP` pin
   and a `do {} while (0)` scaffold. It was not landed here.
3. **Signedness.**
   - 0x0A, above.
   - Steps: the plain `short` spelling is exact on 215 rows, including rows that declared the tables `u16[]`.
     10 rows keep `((u16 *)dirStepX)[i]` because their `lhu` feeds a comparison or shift.
4. **-G / small data.**
   - cc1 marks an extern small when its declared size is at most -G. 2.7.2-cdk rows at the default -G8 then emit a
     `la` macro instead of explicit lui/addiu.
   - dungeon/func_800B0770 declared the step tables `s8` (1 B), and retail matches that `la` form. It is not exact
     with `short[8]` (16 B), so it is refused and keeps its local declaration.
   - Every shared type must stay larger than the largest -G of its rows. The step tables and the block are both
     above 16 B.
5. **Byte views.** dungeon/func_80D3CBF8 (2.8.1-G0) reads the tables as `u8[16]`. The cast view changes a
   register choice (9 differences), so the row is refused.
6. **Aggregate copies / alignment.** Neither object is ever copied (no lwl/lwr, no block moves), so this was not
   exercised. Watch for it when a struct replaces an array that is copied (`D_800814A0`?).
7. **SLUS object identity.** `%lo(D_80083462)` -> `%lo(D_80083460+2)` changes a relocation's symbol, not its
   bytes. Overlay rows are byte-compared, so this is fine. A SLUS row with that change needs
   `verify.py --rebaseline-slus` after the SLUS gate. The one SLUS row here keeps the base form, so its listing is
   identical. Its `.extern D_80083460` size changes from 20 to 32 bytes, and verify.py still reports the object
   identical: the undefined symbol's size is not emitted or is masked.
8. **Non-split cells are not byte-invisible.** A load+store of one field in stock 2.7.2 CSEs the field address
   into `la g+off` / `op 0($r)`. Retail's `la g` / `op off($r)` is the split form (hazard 2).

## 6. Scaling recommendation

- **Per-object batches.** A batch is one object and all of its rows, landed through one apply.sh-style script
  (one gate_all plus one SLUS build per batch).
  1. Census the pinned listings (tools/census.py + flow.py: about 3 s for 1,122 rows).
  2. Take widths and signs from retail, and resolve unions with a field-type A/B over the rows.
  3. Run the automatic rewrite to plain fields (`rewrite_blk(loose=True)`), then verify.
  4. Fall back to the view spelling.
  5. Hand-write the natural spelling for the remaining array-view rows.
- **Cost measured.**
  - Automatic rewrite plus verify: 231 rows in 41 s and 857 rows in 2.5 min (6 workers), about 0.2 s of wall time
    per row, with no model involved.
  - Hand natural spelling: 13 rows in this pilot, a few minutes of agent time each.
  - Hit rates without hands: steps 225/229 (98%); block 797/857 (93%, 100% of rows whose declarations match a
    field). The remaining ~7% are array-index views.
- **Next generator.** Map `D_base[i]` / `((T *)&g)[i]` to the field at `i*sizeof(T)`. That turns the 53 view rows
  into natural field accesses; the hand spelling was exact on 8 of 8 of them.
- **Next objects,** by reach:
  - D_800814A0 (723 rows, all binaries; it is the ORed-flags word, and SLUS -G8 rows use $gp, so watch hazard 4)
  - D_80083228 (578)
  - D_80083498 (641 references, town + dungeon, passed by address: its layout comes from callee arguments)
  - D_80083160 (403, all binaries)
- **Readability pass afterwards.** The step rows still carry m2c byte arithmetic
  (`*(s16 *)((u8 *)dirStepX + direction * 2)`). Now that the type is shared, a generator can turn those into
  `dirStepX[direction]`, verified per row.

# Phase 2 (r78, owner-approved progression): the view generator, the rest of dungeonStatus, and 0x800814A0

## 7. The generator: `tools/consolidate.py`, one object spec per object

`objects/<var>.json` describes each object:
- `base`: its address
- `var`: the readable name
- `header`: its shared header
- `syms`: a regex matching every address-named symbol inside the object
- `fields`: `[off, name, ctype, size, signed(, count)]`; a field named `""` makes a scalar object

`consolidate.rewrite(text, obj)` removes the row's local `extern` declarations of those symbols. It then rewrites
every use to the field it addresses, computing the offset as `addr(sym) - base + k*sizeof(declared element)`. It
handles these spellings:
- `S[k]` with a literal index
- scalar `S`, and `*S` on a decayed array (as `S[0]`)
- `&S...`
- `S.member` through a LOCAL view typedef, which it lays out itself

It spells each result as follows:

| case | spelling |
|---|---|
| same size and sign | `var.field` |
| a read of a differently-signed view | `(T)var.field` |
| a simple store | `var.field = x` |
| a compound op across the int/pointer boundary | `*(T *)&var.field` |
| no field of that size (a union site) | `*(T *)((u8 *)&var.field + d)` |
| decayed array / computed index | `((T *)&var)` (view) |

It then drops any local view typedef nothing uses any more and includes the header. Strings and comments are
never rewritten; asm strings keep their D_ spelling, which still links.

- `tools/drive3.py OBJ1,OBJ2`: every row that spells any of the objects by address gets all of their rewrites in
  one text, verified once. The fallbacks are the phase-1 view spelling for dungeonStatus, and each object alone.
- `tools/pins2.py`: the pin check for migrated rows.
- To run a new object: census the pinned listings (`tools/census.py TAG REGEX`; `tools/flow.py` now also records
  `%gp_rel`), write the spec, then run drive3.

# Phase 3 (r78): the local-pointer fold, GameWork (0x80083160), and a function address declared as data

## 12. The local-pointer fold: `consolidate.rewrite_pointers(text, obj, mode)`

m2c often spells an object as a local pointer:

    u8 *state = &D_80083460;   /* or (u8 *)(&dungeonStatus) */
    ((S_x *)state)->unk_0A ...

The fold finds every local `p` whose assignments are ALL the same object address (`&var` or `&var.field`,
through any casts). It refuses unless every other use of `p` is a recognised object access:
- `((V *)p)->m`, where V is a local view the tool lays out itself, keyed by typedef name and struct tag
- `p->m`
- `*(T *)(p + k)` and `*(T *)((u8 *)p + k)`
- `((T *)p)[k]`, `p[k]` and `*p`

It also refuses a register-pinned `p` and any `p` whose address is taken. Then it rewrites in one of two modes:
- **direct**: `p` and its assignments go, and each access becomes `var.field`.
- **typed**: `Type *p = &var;` and each access becomes `p->field`. This keeps the pointer variable, which is
  sometimes what forms retail's base register.

Both modes use the same emitter as phase 2 (`emit_field`: casts only at sign or int/pointer mismatches, a view at
union sites). Several identical declarations of `p` are the matching and NON_MATCHING arms of one function, and
they are edited in lockstep. `drive3.py` now tries every plan with the fold (direct, then typed) before it tries
the plan without it.

The fold also handles two more cases:
- An opaque view (an incomplete `struct S` whose address is all the row takes) becomes `((struct S *)&var)`.
- Plain `struct Tag {...};` definitions count as views too.

## 13. `GameWork gameWork` at 0x80083160 (include/shared/game_work.h), which absorbs 0x80083228

- **One object.** The census covers 1,095 rows touching 0x80083160..0x8008335F (`census/g83160w.jsonl`,
  `tools/layout.py`). Rows reach every offset from 0x000 to 0x1FC from one lui/addiu base of 0x80083160. That
  includes 0x0C8, which is **D_80083228**: 57 rows read it through the base, and 567 rows read it on its own.
- **0x80083228 is a field, not an object.** Declared as a stand-alone `short`, 60 rows miss. As a stand-alone
  10-byte aggregate, 575 of 576 rows are exact. That already said "aggregate (MEM_IN_STRUCT)"; the base census says
  which aggregate. The field is `viewAngle`.
  - It is read-only in C (lh 1,134 sites).
  - `(viewAngle + obj->angle + 0x100) >> 9 & 7` picks an object's 8-way directional sprite, so it is the view's
    rotation (0x1000 = one turn).
- **Layout.** 112 fields, generated from the access census:
  - width is the majority access width
  - lh => signed; lhu-only => unsigned; store-only => signed
  - unaccessed gaps become `pad_XXX`
  - pointers where lw and the declarations say so (0x000, 0x008, 0x010, 0x0CC, 0x0D0, 0x0F0)
  - union sites (a wider or narrower access) are reached through views at the use:
    - 0x004: 2 lbu over a u16
    - 0x008: 1 lhu over a pointer
    - 0x0A8: lw/sw over three bytes
    - 0x0AC/0x0B0/0x0C4/0x0C8: one word copy

## 22. `EntityRec` (include/shared/entity.h) supersedes the generated Rec_D_800E3D7C / Rec_D_800814A8

- **One source.** `tools/entity.py` holds FIELDS (offset, C type, name, size, sign, evidence) and generates the
  header (`python3 tools/entity.py header`).
- **Layout.** It is the generated record's 0x12C bytes.
  - Every "accessed as both" union is resolved to one field type: the majority retail access.
  - Minority reads get a cast at the use: `((u16)e->x.w.i)`, `((u32)e->flags1C)`.
  - A different-size access is a view at the use: `(*(u8 *)((u8 *)&e->unk_10 + 3))`.

    on sign.
  - Rec_D_800814A8 turned out to be another view of the same record: its facing at 0x2A and fields at
    0x58/0x6A/0x88/0x9A coincide. Its extra fields filled EntityRec pads (0xA8, 0xAC, 0xB0, 0xF4, 0x102, 0x10C).
- **Unions resolved.**
  - x/y/z (0x00/0x04/0x08) are `Fixed1616` (union { int v; struct { u16 frac; s16 i; } w; }). Retail reads them
    whole (lw) and as the integer half (lh +2). World coordinates are tile*64+32 (func_800A08A0), and z is compared
    with the ground height.
  - flags1C: s32 vs u32 is byte-neutral (A/B: 532 exact both ways). s32 needs fewer adaptations (127 vs 166), so
    it stays s32.
  - unk_6D: s8 kept on the same test.
- **Names at high confidence:**
  - x/y/z

  - facing (0x2A): `(viewAngle + facing + 0x100) >> 9 & 7` picks the sprite

  - everything else stays unk_.

  header would collide with them. apply5's preflight refuses on any collision.
- **Rewrite** (`entity.rewrite`): a member access is rewritten only when its base is provably the record.
  - Proof means `((Rec_X *)expr)` or a variable declared `Rec_X *`. The base start is found by walking back
    over the postfix expression.
  - The type name becomes EntityRec in code only.
  - `#include "records/Rec_X.h"` is replaced by shared/entity.h when nothing else in the row needs the old record.
- **Hidden scaffolding.** The generated record hides `volatile` in `at00_vs32` variants. A row using one is

# HOW TO CONTINUE (cold start for a fresh agent)

## The goal and the rules
Turn address-named globals and per-function m2c views into shared, named types, keeping every row byte-exact.
Owner rulings are in docs/TYPE_CONSOLIDATION.md:
- one definition per object across all binaries
- name only at relatively high confidence; unknowns stay unk_XX
- resolve unions where retail evidence allows
- never edit src/include/config/tools directly from a lane: write an apply script the orchestrator runs under
  build_ovl/work/land.lock

## Workflow per object (one object or family = one batch)
1. **Census the pinned listings.**
   `python3 tools/census.py TAG 'REGEX'` compiles every row whose text matches REGEX (cc1 only, fast) and records
   every access with `tools/flow.py`: direct, base (lui/addiu then off($r)), indexed, %gp_rel.
   Output: `census/TAG.jsonl`.
2. **Derive the layout.**
   `python3 tools/layout.py census/TAG.jsonl BASE END [out.json]` prints offset/opcode counts.
   - Width = the majority access.
   - lh/lb => signed; lhu-only => unsigned; store-only => signed.
   - A different-size access is a union site: reached through a view at the use.
   - Rows reaching all offsets from ONE base prove one object. Separate luis per symbol in the same block prove
     separate declarations.
3. **Write the header** in `inc/shared/<obj>.h`: plain C types, no includes (or only other shared/ headers),
   field comments carrying the evidence. **Write the spec** in `objects/<var>.json`:
   - base, var, header, syms (a regex for every address-named symbol inside the object), census, fields
     `[off, name, ctype(s8|u8|s16|u16|s32|ptr), size, signed(, count)]`
   - optional: type, global_decls, extra_views, drop_views, ptype
   - A `""` field name makes a scalar object. A spec whose var is its own D_ symbol keeps the address name.
   - **Keep paths repo-relative**: the scrub hook refuses home paths, and `consolidate.repo_path` resolves them.
4. **Readable name?** Put a row in `names_addN.tsv` (addr, D_sym, name, evidence). ccproc/match.py spell it back to
   D_ before the assembler, so no relocation changes. Otherwise keep the D_ name.
5. **Run.** `TAG=_x CANDDIR=candN python3 tools/drive3.py OBJ1,OBJ2,...` rewrites and verifies every row that
   spells any of the objects, all objects in one text.
   - Plans are tried in order: every object natural (with and without the local-pointer fold, direct then
     typed), then fallbacks.
   - `ok` means verify.py exact, or `rebaseline_slus` (see hazards).
   - For the entity record the pseudo-object is `objects/EntityRec.json` (kind "entity" -> tools/entity.py).
6. **A/B any uncertain choice by exact counts**: scalar vs aggregate, a field's sign, field vs separate object.
   Use `TYPES_INC=<alt include dir>` or a spec variant, and `NOSTAGE=1`.
7. **Pins.** `PINRES=<results file> PINCAND=candN PINOUT=pinsN.jsonl python3 tools/pins2.py` erases each pin alone
   and all together on the migrated text and on the tree text. A pin that falls only on the migrated text is
   freed by the type. Stage the text in `pinsN/` with `.base_sha` = the sha of the applyN candidate.
   Any result that is exact only at ANOTHER cell must also pass tools/fidelity/cell_retail_check.py before it is
   reported.
8. **Deliver.** Copy `applyN-1.sh` to `applyN.sh` (string replacements: payload/cand dirs, BUSY file, collision
   type list, tag, journal headers). Write the manifest (`candNf/MANIFEST.tsv`: row, path, verified sha, plan,
   `rebaseline`), `payloadN/` (every shared header + names_add.tsv) and a 40-row cross-binary sample list.
   `bash applyN.sh --dry-run` must say 0 skipped.

## Known hazards (each one was measured, not assumed)
- **-G and declared size.** cc1 treats an extern of size <= -G as small data (%gp_rel, or a bare macro that the
  assembler expands with $at). Retail's address form therefore bounds the ORIGINAL declaration size per TU:
  - objectFlagBlock: 9..16 bytes
  - dungeonStatus: > 16 at -G16
  - Pick a shared size that satisfies every row's -G. Scalars break -G8 rows.
- **Scalar vs aggregate.** A declaration's aggregate-ness changes codegen through MEM_IN_STRUCT alias classes and
  address CSE, even for offset-0 accesses.
  - 0x800814A0 was declared both ways in the original: 19 rows stay scalar.
  - 0x80083228 only works as a field of the aggregate gameWork.
  - The pointer globals only work as scalars, and freed four pins.
  - Always A/B.
- **Views vs fields.** For a global, `((T *)&g)[i]` / `*(T *)((u8 *)&g + k)` fold to `%hi(g+k)` and miss where
  retail formed a base. `g.field` / `g.arr[k]` keep `lui/addiu g` + off($r). Prefer natural fields and use views
  only at genuine union sites. Through a pointer, casts at the use are safe.
- **Separate objects.** Two symbols reached from one base in one block would share a base register if made
  fields of one struct.
  - objectFlagBlock vs D_800814A8: 23 of 38 functions miss. Keep them separate.
  - slus/w_8004D5D0 bases at 0x80083178 inside gameWork: a second declaration in that TU. It keeps its D_
    spelling.
- **SLUS rebaseline rows.** verify.py compares SLUS rows by object identity. A relocation whose symbol changes
  but whose address does not (D_80083160+24 for D_80083178) reports "not exact" although the bytes match.
  - check.py's `abs_listing` proves them.
  - The apply script runs `verify.py --rebaseline-slus` after the SLUS image MATCH
    (tools/lanes/land_slus_rebaseline.sh).
- **raw vs live include.** Since e8874f3b verify.py's CLI compiles current SLUS texts against the live include/
  (it was the frozen raw/include, which lacks include/shared/). Lane scoring (kitlib.score_at) inlines shared
  headers into a temporary copy (`check.inline_and_respell`, recursive).
- **Name collisions.** New type/object names must be unused as identifiers anywhere in src/ and include/ (local
  typedefs such as Entity, DungeonStatus, Fixed32 exist). The apply preflight enforces it.
- **Landed shared headers are immutable to apply scripts.** The preflight refuses a changed header. Adding fields
  or retyping an extern needs an explicit header-update step with its own verify of every row that includes it.
- **Hidden scaffolding in generated records** (volatile union variants): exposing it would grow the row's
  scaffolding, so such rows are refused.
- **Busy rows.** Skip r78_* `out/` candidates with a `.base_sha` younger than an hour; apply scripts re-check at
  run time.
- **Plural SLUS partitions** (slus/code, code2, w_8003E34C, ...) cannot be compiled alone. Skip them.
- **Never** edit NON_MATCHING arms except in lockstep (rewrite_pointers handles identical duplicate
  declarations).
