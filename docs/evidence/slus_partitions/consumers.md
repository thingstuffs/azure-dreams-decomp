# SLUS collector-row consumer inventory

Read-only inventory of `tools/` on 2026-09-24. No manifest, registry, recipe, source, tool, or ledger file was changed. A collector means one existing logical row and editable C path whose emitted functions would be assigned to several physical module objects. This report maps current assumptions; it does not choose a schema or certify a partition.

`tools/slus_module_context.physical_stem` has no other direct `tools/` caller found; `SlusView` has its own `physical_stem` at `tools/fidelity/slus_iso.py:113` and uses it internally. Existing tests that encode the singular contract are `tools/tests/test_slus_module_context.py:38-106`, `test_slus_module_member_scope.py:45-136`, and the module evidence/ownership tests. These are the narrow regression seams for a schema extension.

Coverage remains keyed to the original row. `tools/registry.py:71-90` derives its one ID and byte size from the split edge and `config/func_sizes.json`; `tools/levels.py:281-349` evaluates that row's current and raw text, while `:351-386` imports `valid_placements()` for the SLUS L4 placement criterion. `tools/status.py:8-33` counts the registry rows/bytes and reports module certificates. Thus the denominator need not change, but placement must be an all-owner predicate. The existing pin, tail-jump, fidelity, and L5 residue rules should remain per original row.

For **emitted** function sets, use object symbols rather than C reference/definition regexes: `tools/fidelity/objread.py:82` parses ELF `STT_FUNC`; `tools/fidelity/aspsx_diff.py:129-158` builds text-function extents from those symbols; `tools/fidelity/slus_iso.py:151-155` obtains defined `T` symbols from a compiled object with `nm --defined-only`; and `tools/fidelity/probe_slus_module_build.py:58-68` reads defined linked symbols with `nm -S --defined-only`. The latter `T` filter sees only global text symbols, so the ELF `STT_FUNC` reader is the stronger inventory when local functions matter. `tools/verify.py:50` (`DEF_SYM`) and `tools/registry.py:20` (`DEF_RE`) scan C text; `test_slus_module_member_scope.py:45-91` already documents that the registry scan can mistake a prototype for a definition. Those scans are useful for source validation, not proof of emitted ownership.

Minimal architecture touchpoints, in dependency order: extend manifest validation/build projection with an explicit collector-to-fragment function partition and unambiguous per-owner recipes; add plural context/fingerprint/compile APIs that preserve original row identity and candidate editing; teach the isolated gate and verifier to fan out a candidate and compare the whole retail image; make genuine-ASPSX and ownership receipts prove each owner's emitted subset and their exact union; then require all-owner certification in `valid_placements`. Registry, denominator, and L4/L5 policy can stay row-based. Until all gates exist, new collector declarations should fail closed in singular consumers.
