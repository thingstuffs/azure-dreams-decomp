# Static shared-body recovery, run 6

This cohort follows the run-5 source commit. It adds shared placements of
existing ordinary C bodies, using the current home recipe and complete
destination-section comparisons. No compiler, assembler, source function,
native module allocation, or placement-contract implementation is changed.

The static inventory retains every explicit unresolved graph record and
adds physical sparse-view holes, classified code regions without a C row,
and unclassified container residuals. Raw resource spans are not described
as code merely because they lack C. Individual function tasks overlap this
physical inventory and are not added to physical byte totals. Missing
runtime observations are not evidence of dead or debug code.

Loose instruction signatures are discovery filters only. Each candidate
home is compiled with its current content-keyed ordinary recipe. Every
external relocation is solved consistently, the complete original function
section is linked at the selected destination, and all output bytes must
equal retail. Unrelated module sections and compiler-local tables grant
no ownership to a target body. Prefix-bearing homes remain held.

Entry review requires a source JAL, source callback-address construction,
an explicit table/loader callback word, a conditional direct-call closure
from the resource loader's two callback roots, or a complete gap bounded
by two registered source extents. A matching body without an independent
entry witness is held. Static call closure explores both branch outcomes
and stops at computed jumps; it does not assert a runtime hit.

The first reviewed cohort contains 81 new placements, totaling 36,272
bytes: 66 dungeon, 10 town, and five MAIN entries. Thirty-six other exact
sections were already registered C; only their stale unresolved byte-map
accounting is repaired. They add zero source coverage. The dungeon reset
leaf removes only its 40-byte suffix from a prior nonmatching accounting
record and retains the original prefix. No matching row is retired.

Kewne container offset 0x9C0054 has a complete 1,864-byte match to the
current movement home `dungeon/func_80976434`. In `bank_9bf000` its address
is 0x80171854, independently referenced by existing source JALs at offsets
0x9BFD8C and 0x9C0F28. The inherited hold's address 0x80170854 did not
describe this current load view. Resolving the physical source hold does
not establish a new runtime observation at either address.

Registration is keyed by row, source identity, physical extent and existing
load image. All authority and source checks finish before publication;
wrong load views, overlapping owners and late source drift fail closed.
The row registry and native-module graph are generated by their project
tools. The hash-guarded link graph is regenerated exclusively with
`tools/link/graph.py capture`.

The replay package re-follows current source homes, compiles current
recipes, and derives every destination binding again. Source comments,
renames, or folds can be accepted only after current complete-section
equality; a historical hash never substitutes for this proof. Commit the
cohort before running the final changed-path union with `prove_scope.sh`,
then run the row database and source-layout checks.
