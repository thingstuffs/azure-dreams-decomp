# Independent review: `func_8002626C` dungeon noreturn census entry

## Verdict

Approve the narrow metadata correction: delete only `func_8002626C` from
`config/noreturn_syms.dungeon.txt`. The current global entry contradicts the
helper's contract and changes the only reviewed call from retail `jal` to `j`.
No source, maspsx/pass, or other census change is supported by this review.

Publication remains conditional on the planned two-row, all-window, SLUS, and
row-database gates. This review ran no compiler or export and changed no
production/config file.

## Source and contract evidence

- `src/dungeon/func_819C0A6C.c` defines `void func_8002626C(...)` with ten
  arguments and no noreturn attribute. Its null-allocation path and populated
  path both reach the function end normally.
- `src/dungeon/func_819C0C18.c` has the matching ordinary ten-argument extern.
  Its sole call is inside a two-iteration particle loop; execution increments
  `particle_index`, tests the loop, and continues the state handler after the
  call. Treating the helper as non-returning is semantically inconsistent with
  this caller.
- The target has no current zero-argument noreturn declaration. The one other
  noreturn declaration in the caller excerpt is for `func_80026924`, not this
  helper. Existing candidate/TU self-service for real local noreturn
  declarations is unaffected by removing this global name.
- A bounded exact-name search found only the definition, this caller, and the
  census line. `config/names.tsv` contains no `func_8002626C`, `819C0A6C`, or
  `819C0C18` mapping, so it supplies no renamed semantic alias or hidden second
  contract for this symbol.

## Causal control

`controls.json` uses the same pinned candidate source in both linked-strict
controls (`source_sha256`
`0933595549200627668490c4bc66b2103baffa9021b2872d5fb4fb9dbf41b6e1`).
The raw compiler assembly is byte-identical between controls and contains:

```asm
jal func_8002626C
sw  $2,32($sp)       # delay slot
```

With the current census, maspsx alone changes that pair to:

```asm
j   func_8002626C    # maspsx: tail-call jal->j (LEAD 18)
sw  $2,32($sp)       # delay slot
```

The current-census linked result is 1336/1336 bytes with only word 210 wrong:
generated bytes `9b980008` versus retail `9b98000c`. Removing only this name
keeps the source and raw assembly fixed, restores `jal`, and produces exact
1336/1336 bytes with generated SHA-256 equal to retail SHA-256
`81db658d100661fc70078817c233ded432145d110bb1ceb6c106e56e88cf6101`.
The pin-free source remains nonexact at 1328/1336 under both censuses, so this
metadata correction does not claim to remove the candidate's remaining source
pin or solve the free-version shape.

## Audit scope and limits

`audit.py` imports only the established declaration parser, then explicitly
scans current `src/dungeon/*.c`; that path resolves to the repository's real
`<repo>/src/dungeon` directory. Its target record reports no
current declaration and exactly the two current source files above. The audit
counts are 1045 present census names, 113 currently scanned zero-argument
noreturn declarations, 110 after known false-member subtraction, 935 stale,
and zero missing.

The build-side path is also unambiguous:
`build_ovl/config/noreturn_syms.dungeon.txt` is a symlink to the canonical
`<repo>/config/noreturn_syms.dungeon.txt`. Thus the proposed
single-line edit reaches both build views directly; it needs no export or
duplicate-file update.

Those aggregate counts are advisory, not authority for a 935-name prune. The
durable generator has historical/container evidence rules and tracked overlay
globs that are broader in purpose than this current-source inventory; other
names may still serve assembly, alias, window, or family-wide behavior not
tested here. `func_8002626C` is independently safe to remove because its real
definition returns, its current caller requires return, it is argument-taking,
the alias table has no alternate mapping, and the one-name linked control
isolates the exact retail opcode.
