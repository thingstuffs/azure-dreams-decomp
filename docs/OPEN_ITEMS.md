# Choosing further work

Use [generated status](../STATUS.md) for current coverage, source-quality
residues and proof freshness. This page avoids duplicating changing counts or
treating an old private candidate as a contribution-ready patch.

| Area | Useful contribution | Evidence to provide |
|---|---|---|
| Names and summaries | Improve a weak or unknown role | Developer strings, dispatch/call relationships or supported data use; [naming rules](SYMBOLS.md) |
| Shared types | Replace compatible local views with one supported type | Offsets, widths, signedness, ownership and all dependent users; [type workflow](TYPE_CONSOLIDATION.md) |
| Source shape | Replace a pin, pseudo-call or awkward control flow | Source mechanism, registered recipe and scoped retail verification; [fidelity limits](FIDELITY.md) |
| Module/placement proof | Complete a reviewed boundary or renew stale proof | Current full TU, storage ownership, genuine comparison and affected window/image checks |
| Disc coverage | Resolve an unknown span or improve data typing | Bounded reader/load evidence and interval accounting; [byte maps](LINK_LISTS.md) |

Before choosing an item, check the current source and latest decision/evidence
record. Old lists mention already retired headers, repaired SDK routines,
superseded signatures and certificates from earlier tool fingerprints. A stale
certificate needs a fresh proof; it is not evidence that the underlying bytes
changed. Matching registered rows does not settle unregistered library code or
other non-C spans.

Report a bounded result with the affected stable IDs and physical source paths,
what improved, what was verified, and what remains unknown. Keep a precise hold
when the source or ownership evidence is incomplete. [The documentation index](README.md)
has lookup and verification examples. The
[decision record](evidence/r97_decisions.md) retains closed investigations and
rulings as history rather than an active queue of private work directories.
